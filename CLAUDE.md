## Environment

`.env` (Vite, all vars must be `VITE_`-prefixed):

- `VITE_API_BASE_URL` — gateway base, e.g. `https://nsb-api.corelpr.com/api/v0`
- `VITE_API_SERVICE_CHANNEL` — sent as the `x-service-channel` header on every request and used to filter SSE events; currently `user-management`
- `VITE_IS_DEV` — when truthy, `DropdownApi`, `CoreDataApi`, and `UsageChartApi` short-circuit to the fixtures in `src/mocks/` instead of hitting the network. Set it when the backend is unavailable.

`__APP_VERSION__` is injected by `vite.config.ts` from `package.json`.

## Architecture

This is a Thai-language police LPR (license plate recognition) admin console — the user/permission-management front-end for a larger "NSB core" backend. React 19 + Vite + TypeScript, MUI + Tailwind v4 side by side, Redux Toolkit for a small amount of global state.

### API layer

**All** network access goes through `src/api/fetchClient.ts`. It is not a generic wrapper — it owns cross-cutting behavior that must not be reimplemented per-call:

- Injects `x-service-channel`, `Content-Type` (unless `isFormData`), and `Authorization: Bearer` from `localStorage.accessToken`.
- Attaches `x-latitude` / `x-longitude` from `navigator.geolocation` on **every** request (the backend audits location); geolocation failure degrades silently. The fix is cached for 60s (10s after a failure) and concurrent callers share one in-flight lookup, so a page firing many requests does not trigger many GPS lookups.
- Drops `null`/`undefined` query params rather than serialising them as the string `"undefined"`.
- On 401/403 it runs a single-flight refresh (`/user-management/users/refresh`, cookie-based) with a queue so concurrent failures share one refresh, then retries once. A second failure dispatches a `window` `"force-logout"` event.
- `credentials: "include"` always — the refresh token lives in an httpOnly cookie, only the access token is in localStorage.

Options beyond `RequestInit`: `queryParams`, `skipAuth`, `isFormData`, `isStream`, `retryCount`.

Feature APIs live in `src/features/<domain>/api/*Api.tsx` as plain exported async functions returning typed responses. The masterdata getters in `DropdownApi.tsx` are generated by a `createGetter(endpoint, mock)` factory — add a new lookup there rather than hand-rolling another GET-plus-mock function. Backend services are distinguished by path prefix: `/user-management/*`, `/core-data/*` (cameras, checkpoints, watch-groups, camera-groups), `/masterdata/*` (dropdown reference data), `/log-management/*` (statistics), `/upload/*`, `/police/*`.

### State

Redux holds only two slices (`src/store/store.ts`):

- `authUser` — the logged-in user incl. their permission tree; **persisted** via redux-persist (`persist:root` in localStorage) and the only whitelisted slice.
- `dropdown` — masterdata reference lists (provinces, agencies, positions, …), populated by a burst of `createAsyncThunk`s fired from `App.tsx` once a user id is present. Not persisted. Thunks and their reducers are generated together by `createDropdownThunk(key, loader)`, so a new list needs one line plus a `DropdownState` field.

**Select individual fields, never the whole slice.** `useSelector(s => s.dropdown)` re-renders the component on all ~26 state updates the login-time thunk burst produces; `useSelector(s => s.dropdown.agency)` re-renders only when that list changes.

Everything else is component-local `useState`. Page components are large and hold their own data-fetching, pagination, and filter state — follow that pattern rather than introducing new slices.

### Auth & session lifecycle

`App.tsx` is the session coordinator: it hydrates theme/language from localStorage, kicks off dropdown loading, redirects to `/login` when no access token is present, listens for the `"force-logout"` window event from `fetchClient`, and opens an SSE stream (`useSse("force-logout", …)`) so the backend can remotely terminate sessions.

`useSse` (`@microsoft/fetch-event-source`) connects to `${API_BASE_URL}/events` and **ignores any event whose `data.serviceChannel` doesn't match `VITE_API_SERVICE_CHANNEL`**.

`useForceLogout` is the single logout path — it clears `accessToken` + `persist:root`, clears the Redux user, and navigates to `/login`.

### Permissions

The server returns a `GroupPermissions` tree on the user: `ui[uiKey].enabled`, `ui[uiKey].groups[groupKey] = "none" | "active" | "edit"`, and `ui[uiKey].prints[groupKey]`. Gate UI with `usePermission(uiKey, groupKey)` which derives `canView` / `canEdit` / `canPrint` / `isReadOnly` / `noPermission`.

`uiKey` is a service (`"user-management"`, `"log-management"`); `groupKey` is a page (`"manage-user"`, `"add-approve-user"`, …). The authoritative catalogue of both — and what the permission editor UI renders — is `src/hooks/usePermissionUiList.tsx`. **Adding a new permission-gated page means adding an entry there, a route in `App.tsx`, a dock entry in `useDockItems.tsx`, and the i18n keys under `permission.ui.*`.**

### Routing & layout

Flat route table in `App.tsx`: `/login` standalone, everything else nested under `MainLayout` (fixed 64px navbar + looping background video + `Watermark` stamping the user's hash id and agency across the page + a floating `DockDrawer` menu, hidden on `/`).

### i18n

`react-i18next` with `i18next-xhr-backend` loading `/locales/{th,en}/trans.json` at runtime from `public/` — translations are **not** bundled; edit both JSON files. Default and fallback language is `th`. Many hooks that build UI lists (`useDockItems`, `useColumnItems`, `usePermissionUiList`) are `useMemo`'d on `t` and `i18n.language` — keep that dependency array intact or labels stop updating on language switch.

Thai dates use the Buddhist era: `src/utils/buddhistEraAdapter.tsx` subclasses `AdapterDayjs` (+543 on year) and is what `date-picker-buddhist` uses.

### Theming

`src/hooks/useTheme.tsx` defines ~18 named palettes and writes them to CSS custom properties on `<html>` (`--primary-color`, `--primary-color-rgb`, `--main-bg-color`, `--tertiary-color`, …), persisting to `localStorage["wd2-theme"]`. Component styling reads those variables (`var(--primary-color)`, `rgba(var(--tertiary-color-rgb), 0.85)`) — use them instead of hard-coded colors so themes keep working. `ThemeProvider` is the only owner of these variables; do not set them elsewhere.

## Conventions

- Components: one directory per component in `src/components/<kebab-case>/<PascalCase>.tsx`.
- Imports are grouped with `// Material UI`, `// Components`, `// Types`, `// Hooks`, `// i18n`, `// Utils`, `// API`, `// Store` comment headers. Match this in new files.
- `verbatimModuleSyntax` is on — type-only imports must use `import type`.
- `noUnusedLocals` / `noUnusedParameters` are on; unused symbols are build errors.
- MUI is imported per-module (`import Box from "@mui/material/Box"`), not destructured from the barrel.
- User-facing dialogs/confirms go through the helpers in `src/utils/popupMessage.tsx` (`PopupMessage`, `PopupMessageWithCancel`, `PopupMessageWithCancelAndDeny`), not `window.confirm` (native dialogs also break browser automation). They resolve a promise the same way the old SweetAlert2-backed versions did; under the hood they push onto an imperative store (`src/components/confirmation-dialog/confirmationDialogStore.ts`) rendered by the single `<ConfirmationDialog />` host mounted in `main.tsx`, animated with framer-motion.
- Excel export via `exportExcel` in `src/utils/exportData.tsx` (exceljs + file-saver); PDF via `src/pdf/` (pdfmake, fonts loaded from `fonts/` through the cached `getConfiguredPdfMake()`). Both libraries are **dynamically imported** at their point of use and together account for ~2.4 MB — keep them out of module-level imports or they land back in the initial bundle.
- `src/utils/encryption.ts` AES-obfuscates user ids for URLs. It uses a hard-coded key and is obfuscation, not security — do not treat it as an access control.
